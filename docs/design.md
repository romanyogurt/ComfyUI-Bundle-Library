# Bundle Library 설계 개요

2026년 10월 16일, 노드 0.0.12(`f3c5d45`)의 소스와 문서를 기준으로 정리했고, 0.0.13(목록 도구줄),
0.0.14·0.0.15(여러 번들 선택, 편집 잠금), 0.0.17(창의 명령, 질문창, 편집기 모델), 0.0.18(실행 일관성), 0.0.19(태그), 0.0.20(0.0.19 재검증 보완), 0.0.21(내보내기)에서 갱신했다. 이 문서는 현재 구현의
책임과 불변 조건을 설명한다. 파일 형식, API, 오류와 제한값은 [데이터 형식과 API](data-format.md)가
기준이다. 사용법과 테스트 실행 방법은 [README](../README.md)에 있다.

## 번들과 필드의 정체

워크플로는 번들을 UUID로 가리킨다. 번들 이름은 표시용이므로 같은 카테고리 안에서도 중복될 수 있다.
화면은 동명 번들을 UUID의 앞부분으로 구분한다. 이름 변경이나 카테고리 이동은 워크플로의 참조를 바꾸지
않는다.

필드는 번들 안의 이름과 타입으로 매칭한다. 필드 이름은 대소문자를 구분하고, 번들 안에서 고유해야 한다.
필드 이름을 바꾸면 예전 이름을 참조하는 슬롯은 누락 상태가 된다. 필드 배열의 순서는 처음 출력 슬롯을
만들 때 쓰며, 기존 연결의 대상을 순서만으로 다시 정하지 않는다.

## 출력 슬롯과 워크플로 보존

백엔드는 고정된 출력 풀을 선언하고, 프런트엔드가 필요한 슬롯만 보인다. 워크플로에 저장되는
`bundle_id`가 번들을, `slot_spec`이 출력 인덱스별 필드 이름과 타입을 정한다. 화면의 라벨이나 서버에서
다시 받은 목록으로 이 대응표를 추측하지 않는다.

- 같은 이름·타입의 필드는 연결을 유지한다. 연결된 필드가 새 번들에 없거나 타입이 달라도 그 슬롯을
  자동으로 지우거나 다른 타입으로 바꾸지 않는다.
- 새 슬롯은 끝에 추가한다. 연결되지 않은 불필요한 슬롯은 뒤에서부터 LiteGraph API로 제거해 링크
  인덱스가 함께 조정되게 한다.
- 불러오기·붙여넣기·실행 취소 뒤의 `onConfigure`에서 스펙으로 라벨과 타입을 동기 복원한다. 미리보기는
  그 뒤 비동기로 조회한다. 워크플로가 연결된 출력을 같은 자리의 스펙과 다른 이름·타입으로 저장했으면(손으로
  고친 파일 등) 어느 출력인지 알린다. 실행은 스펙을 따르므로 그 링크는 스펙의 필드를 받는다(0.0.18부터).
- 읽지 못하는 스펙은 빈 슬롯으로 바꾸지 않는다. 원문과 출력·링크를 보존하고 안내하며, 호환되는 버전이
  필요하다는 상태를 유지한다. 백엔드는 이 스펙의 실행을 거부한다.
- 라이브러리에서 필드 구성이 바뀌었다고 슬롯을 자동 재구성하지 않는다. 사용자가 번들을 고르거나
  "Update outputs"를 눌렀을 때 조정한다.

슬롯 계획의 순수 함수는 `web/reconcile.js`, 노드 생명주기와 패널은 `web/loader_node.js`가 맡는다.
노드 선언은 ComfyUI V3 API(`comfy_api.latest`)를 사용하고, 화면은 LiteGraph의 생명주기와 DOM 위젯에
의존한다. 입력 순서와 출력 풀을 바꾸는 규칙은 [워크플로와 노드](data-format.md#워크플로와-노드)를 따른다.

## 실행과 캐시

`bundle_library/nodes.py`는 실행 한 번에 번들 스냅샷 하나를 읽어 모든 출력을 만든다. 연결된 출력이
가리키는 필드가 없거나, 타입이 다르거나, 미디어가 비었거나 파일이 없으면 문제를 모아 예외로 실패한다.
예전 결과나 `None`이 정상 레퍼런스처럼 하위 노드로 넘어가지 않게 하기 위해서다.

연결되지 않은 슬롯의 같은 문제는 실행을 막지 않는다. 그 자리에는 이유를 담은 `ExecutionBlocker`를
둔다(0.0.18부터, 그 전에는 `None`). 출력은 연결 여부와 상관없이 캐시되므로, 캐시된 실행 뒤에 그 출력을
나중에 연결한 노드는 `None`을 받지 않고 그 이유("Execution Blocked: …")로 멈춘다. 오류는 그 노드에 보이고 그
뒤의 노드는 실행되지 않지만, ComfyUI는 막힌 노드가 있는 실행을 성공으로 기록한다. 값 변환은 `slot_spec`
전체를 기준으로 하므로 연결되지 않은 유효한 미디어 슬롯도 변환 비용이 들 수 있다. 연결 여부는 제출된
프롬프트 전체에서 본다. 일부만 실행할 때 실행되지 않을 가지에 연결된 문제 슬롯도 실패로 보는 것은 알려진
제한이다.

지문을 계산할 때는 연결 정보를 읽는 hidden `PROMPT`를 쓸 수 없다(빈 값이 온다). `bundle_library/slots.py`가
스펙 순서대로 필드 이름·타입과 값 또는 파일 SHA-256으로, 채울 수 없는 슬롯은 그 이유로 지문을 만든다. 같은
번들은 같은 지문이라 빈 미디어 필드가 있는 번들도 캐시를 쓴다. 0.0.17까지는 문제 슬롯이 하나라도 있으면
지문이 NaN이어서 Load Bundle과 그 뒤의 노드가 매번 다시 실행됐다.

ComfyUI는 실행을 시작할 때 모든 노드의 지문으로 캐시 키를 정하고 노드는 나중에 실행한다. 그사이 번들이
바뀌면 그 키 아래 다른 내용의 출력이 남을 수 있다. 그래서 `fingerprint_inputs()`가 낸 지문을 그 실행의
노드별로 기억해 두고, `execute()`는 읽은 내용의 지문이 그것과 다르면 "changed while this run was starting"으로
실패한다(0.0.18부터). 실패한 노드의 출력은 캐시되지 않으므로 다음 실행은 지금 내용으로 다시 실행된다.

번들 이름·메모·태그·revision·시각과 카테고리·즐겨찾기는 이 지문에 들어가지 않는다. 같은 번들과 스펙에서
그 정보만 바꾸면 하위 노드의 캐시를 유지한다. 전체 캐시 키에는 ComfyUI가 노드 입력 등도 포함하므로,
지문만 같다고 서로 다른 번들 선택의 캐시까지 공유한다는 뜻은 아니다.

미디어 변환은 `bundle_library/convert.py`가 맡는다. 이미지는 core Load Image와 같은 경로의 첫 프레임을,
비디오는 파일을 참조하는 VIDEO를, 오디오는 디코딩한 AUDIO를 돌려준다. 비디오는 소비 노드에서 파일을
읽을 수 있어야 하고, 오디오의 실행 제한은 옛 번들에도 적용된다.

## 내용, 정리 정보와 삭제 상태

번들 내용과 미디어는 ComfyUI 사용자 디렉토리 아래 저장한다. 미디어 원본은 내용 해시로 식별하고,
같은 해시 아래의 바이트가 바뀌지 않는 것을 전제로 한다. 썸네일은 다시 만들 수 있는 캐시다.

카테고리와 즐겨찾기는 `organization.json`에 둔다. 번들의 배치는 UUID를 기준으로 하며, 이 파일의
변경은 번들 내용이나 revision을 바꾸지 않는다. 파일이 없으면 빈 정리로 시작한다. 파일을 이해할 수
없으면 원본을 지키고 정리 변경을 막는다. 카테고리와 즐겨찾기 없이도 번들 내용을 읽을 수 있다.

휴지통은 번들의 `deleted_at` 상태다. 파일은 같은 UUID 위치에 남고, 일반 조회와 노드 실행에서는
제외된다. 되살리면 같은 UUID와 이름을 유지하고 원래 배치와 즐겨찾기로 돌아온다. 이름이 겹쳐도 바꾸지
않는다. 영구 삭제와 미디어 정리는 별개이며, 미디어 참조를 셀 때는 활성 번들과 휴지통을 함께 본다.
참조를 안전하게 판단할 수 없는 파일이 있으면 정리를 거부한다. 옛 `trash/` 폴더의 이관 규칙은
[저장 위치](data-format.md#저장-위치)를 따른다.

## 저장과 호환성 경계

`bundle_library/store.py`는 프로세스 안의 잠금과 같은 파일시스템의 임시 파일·원자적 교체로 쓰기를
보호한다. 편집 저장은 예상 revision을 확인해 다른 편집을 조용히 덮지 않는다. 라이브러리 폴더 하나에는
ComfyUI 프로세스 하나만 쓴다. 별도 테스트 서버는 자기 임시 라이브러리를 사용한다.

`bundle_library/schema.py`는 지원 버전의 번들을 메모리에서 마이그레이션하고 상태를 분류한다.
일반 조회·실행만으로 번들 파일을 다시 쓰지 않는다. 옛 `trash/` 폴더 이관은 별도의 호환 처리다.
구조 불변식, 작성 정책의 경고, 실행 자원 제한을 구분하며, 이해하지 못하는 데이터는 변경을 제한한다.
상태별 허용 작업은 [호환성 정책](data-format.md#호환성-정책)을 따른다.

HTTP 계층은 `bundle_library/routes.py`가 맡는다. 저장소 API 처리와 미디어 검사·썸네일 생성은 작업
스레드에 넘기고, 업로드 본문은 스트리밍하면서 크기를 제한한다. 동일 출처의 쓰기 검사와 웹·Python 버전
불일치 검사는 이 계층의 책임이다. 인증과 네트워크 접근 제어는 ComfyUI를 배포하는 환경에서 다룬다.

## 화면 상태와 저장 시점

라이브러리 편집기는 저장된 번들과 초안을 구분하고, 내용 변경은 Save 때 저장한다. 파일 업로드는 먼저
에셋을 저장하고 나중에 번들이 참조한다. 저장하지 않은 초안이 쓰는 파일을 위해 정리 유예 시간을 둔다.

카테고리·즐겨찾기는 즉시 저장한다. 목록이 갱신되어도 편집기의 초안은 유지하고, Revert는 내용만
되돌린다. 새 번들의 카테고리는 최초 내용 저장 뒤 적용한다. 배치만 실패하면 생성 실패로 숨기지 않고
별도 결과를 알린다.

편집기가 다루는 것은 `EditorModel`(`web/editor_model.js`)이다. 저장본, 초안, 숫자 칸의 입력 원문(해석되지
않을 때도), 필드별 업로드를 갖고, "떠나면 잃을 것"(`changed`: 초안의 변경, 사용자가 입력한 잘못된 숫자,
올리는 중인 파일)을 한 곳에서 판단한다. 상태 표시, Revert, Duplicate, 창의 잠금이 모두 이 판단을 쓴다. 화면은
모델에서 필드 카드 단위로 그린다. 필드를 더하거나 옮기거나 업로드가 끝나도 그 카드만 다시 그려 초점과 다른
카드의 입력이 남는다. 모델은 DOM을 쓰지 않아 `node --test`로 검사한다.

서버를 기다리는 명령은 `Commands`(`web/commands.js`)가 다룬다. 저장, 복제, 삭제, 여러 번들의 작업은 한 번에
하나만 창을 붙잡고(`hold`), 답이 오고 목록을 다시 읽을 때까지 나머지를 잠근다. 그래서 고르기는 저장과 목록
갱신이 끝난 뒤에만 되고, 노드에는 편집기가 보는 번들을 저장된 그대로 넘긴다(`summaryOf`). 오른쪽 칸과 질문층은
각각 한 번에 하나를 보이는 자리(`Slot`)이고, 보일 때마다 번호를 받는다. 늦게 온 답은 자기가 시작된 내용이
아직 보일 때만 그 자리를 바꾼다(편집기 조회, 일괄 결과, 취소된 뒤에 끝난 질문). 목록·검색·휴지통 조회는 요청
세대 번호로 늦은 응답을 제외하고, 필드별 업로드는 마지막으로 고른 파일만 적용한다. 폐기하는 초안의 업로드는
취소한다. 모달의 입력·붙여넣기·드롭은 ComfyUI 캔버스로 전파하지 않는다.

질문층(확인, 이름 입력, 그림 보기)이 열리면 그 뒤의 창은 `inert`라 포인터·Tab·단축키가 닿지 않고, 명령의 입구도
거절한다. Tab은 질문 안을 돌고, 닫히면 초점이 원래 자리로 돌아간다. 질문은 자기 번호로만 닫힌다.

목록 그리기(`renderList`)는 상태를 바꾸지 않는다. 목록·검색·태그 필터가 바뀌면 `listChanged()`가 먼저 여러
번들 선택에서 보이지 않게 된 것을 빼고, 그린 뒤 오른쪽 칸을 맞춘다. 일괄 화면은 고른 입력(옮길 카테고리)을
스스로 보관한다. 고른 카테고리가 지워지면 "카테고리 없음"으로 바꾸지 않고 다시 고르게 한다. 목록이나 검색을
읽지 못하면 마지막 목록과 선택, 새 초안의 카테고리를 지우지 않고 이유만 보인다.

편집기가 떠나면 잃을 것을 들고 있는 동안(초안의 변경, 사용자가 입력한 잘못된 숫자, 올리는 중인 파일)과
저장 요청, 여러 번들의 작업이 나가 있는 동안에는 편집 말고는 잠근다(`LibraryModal.lockReason`). 탐색마다
묻지 않고, 저장하거나 버려서 편집을 먼저 끝내게 한다. 잠금은 화면 요소를 비활성화하는 것과 함께 명령의
입구(`allowed()`)에서도 검사한다. 편집기 머리의 별표와 카테고리는 그 번들 자신의 정리라 열어 둔다. 번들이
처음부터 가진 경고(작성 규칙 밖의 옛 값)와 손대지 않은 새 초안은 변경으로 보지 않는다. 창을 닫을 때만
Save / Discard / Keep editing을 묻는다. 이 잠금은 이 창의 조작만 막는다. 다른 탭·기기와의 충돌은 서버의
잠금과 revision이 막는다.

여러 번들의 선택은 UUID 집합이다(`selection`). 고르기 모드에서도 같고, 노드에 넘기는 "Use this bundle"만 한
번들을 골랐을 때 쓸 수 있다. Shift 범위는 실제로 누른 `(묶음, UUID)` 행을 기준으로 펼친
행 순서에서 구하고 UUID로 줄인다. 검색·필터가 가린 번들은 여러 개 선택에서 빠진다. 여러 번들의 작업
(`runBatch`)은 첫 대기 전에 대상 id, 인수, 본 revision을 고정하고, 답이 올 때까지 창을 잠그며, 결과를 그
작업의 대상 이름으로 보인다. 결과는 사용자가 떠날 때까지 남는다. 답이 없으면 "Stop waiting"으로 잠금을 풀고
완료 여부를 모른다고 보인다. 늦게 온 답은 그 결과 화면이 아직 보일 때만 반영한다. 서버는 정리 파일을 한
번에 쓰고, 번들 파일은 번들마다 쓴다([여러 번들에 한 번에](data-format.md#여러-번들에-한-번에)).

태그의 같음은 한 곳에서 정한다. 서버는 `casefold()`(`bundle_library/tags.py`)를 쓰고, 화면의 `tagKey`(`web/tags.js`)는
그와 같은 결과를 낸다: 소문자 변환과 결과가 다른 문자(Unicode 15.1에서 297자)의 표와, 나머지 문자의 `toLowerCase()`.
표는 서버의 Python으로 만들고, 단위 테스트가 표와 대소문자가 있는 모든 문자(`tests/fixtures/casefold.json`)를 지금의
Python과 맞춰 본다. Python의 Unicode 판이 바뀌면 그 테스트가 다시 만들라고 알린다. 목록에 보이는 이름·태그·
카테고리의 순서도 화면의 `compareText` 하나로 정한다. 태그를 바꾸는 작업(일괄과 라이브러리 전체)은 번들 전체를
다시 검사하지 않고 저장된 번들의 태그만 고쳐, 옛 규칙의 값을 그대로 둔다. 라이브러리 전체의 이름 바꾸기와
지우기는 저장소 잠금 안에서 번들마다 따로 쓰고, 이 버전이 바꿀 수 없거나 읽지 못하는 파일은 나눠 알린다.
창에서는 Tags 칸(`web/tags_panel.js`)이 범위를 보여 확인받고, 창을 붙잡는 명령(`changeTags`)으로 보낸다.

목록을 다시 읽어 열린 번들이 다른 곳에서 다시 저장된 것을 알면(revision이 더 큼), 편집기에 변경이 없을 때만
저장된 내용으로 바꾼다(`refreshEditor`). 새로 읽기가 겹치면 마지막 것만, 편집기보다 새 revision일 때만 적용한다.
창을 열 때 고른 번들은 첫 목록 읽기가 끝났을 때 오른쪽 칸이 처음 그대로일 때만 연다: 그사이 시작한 새 초안이나
다른 화면을 덮지 않는다. 저장 직후 다시 읽기의 일시 오류는 목록 읽기처럼 기억하지 않는다(`_remember`). 변경이 있으면 그대로 두고, 저장할 때 revision 충돌로 묻는다. 창은 탭으로
돌아올 때도 목록을 다시 읽는다.

목록의 끌기 상태(카테고리를 빼는 임시 놓을 곳)는 출발 행이 아니라 창이 관리한다. 끌기가 끝나거나,
창 안에 놓이거나, 목록을 다시 그리거나, Esc를 누르거나, 창을 닫으면 지운다. 출발 행이 사라져 `dragend`가
오지 않으면 끌기 뒤의 첫 포인터 이동으로 지운다. 놓을 곳은 도구줄과 같은 높이라 목록을 밀지 않는다.
팝업 메뉴(`web/dom.js`의 `menu`)는 키보드로 열고 옮기며, Esc는 확인층이 없을 때 메뉴만 닫는다.

묶음 계산은 `web/groups.js`, 동명 번들 표시는 `web/names.js`, 여러 번들의 화면은 `web/batch_panel.js`, 라이브러리
창은 `web/library_modal.js`, 편집기의 모델과 화면은 `web/editor_model.js`와 `web/bundle_editor.js`, 명령과 화면의
주인은 `web/commands.js`, 태그의 같음과 이름 순서는 `web/tags.js`, 라이브러리 전체의 태그는 `web/tags_panel.js`가
맡는다. API 요청과 목록 캐시는 `web/api.js`에 모은다.

## 내보내기와 가져오기

`bundle_library/exchange.py`가 ZIP 형식과 검사를 맡는다. 저장소에는 좁은 기본 기능만 둔다(`files_for_export`:
잠금 안에서 번들 파일의 바이트, 그 바이트를 이 버전이 읽은 결과, 카테고리 이름). 내보내기는 번들 파일을 저장된
바이트 그대로 담는다. 이 버전이 정규화해 읽은 내용(`schema.Loaded.bundle`)이나 화면용 표현(`present`, 요약)을 다시
직렬화하면 이 버전이 모르는 키나 옛 규칙의 값을 잃을 수 있기 때문이다. 그 바이트의 상태는 같은 바이트로
판단한다(`schema.read_checked`). 가져오기(Phase 8b)도 이 경계를 지켜, 쓸 때만 저장소를 거친다.

## 변경할 때 확인할 것

- 슬롯 정책을 바꾸면 저장 왕복·붙여넣기·실행 취소·서브그래프의 연결과 스펙 보존을 확인한다.
- 캐시를 바꾸면 연결되지 않았던 출력을 나중에 연결하는 경우, 필드 내용 변경, 메타데이터만의 변경을
  함께 확인한다. 실제 실행기로 확인하는 `tests/e2e/cache_race.py`를 같이 돌린다.
- 저장·삭제·정리를 바꾸면 옛 형식과 읽을 수 없는 파일의 보존, 휴지통 참조, 부분 실패를 확인한다.
- 화면 갱신을 바꾸면 미저장 초안과 역순으로 도착하는 응답을 확인한다.

관련 테스트는 [README의 테스트 절](../README.md#테스트)에 있다.
[Phase 0 기록](compatibility.md)은 초기 기술 선택의 근거로만 읽는다. 이후 작업과 운영 절차는
comfy-docker 저장소의 `docs/bundle-library/README.md`, `docs/bundle-library/roadmap.md`,
`docs/bundle-library/operations.md`를 참조한다.
